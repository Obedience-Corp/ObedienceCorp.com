Infrastructure for autonomous companies.

Obey is the execution layer for AI agents. While Festival structures what work needs to happen, Obey handles how that work gets done — managing agent sessions, enforcing security, metering usage, and syncing state in real-time.

It runs as a local daemon on your machine, exposing a control plane that any client can connect to: CLI, TUI, mobile, or web. Agents from any provider — Claude Code, Codex, OpenAI, or custom tooling — run as managed sessions with full lifecycle control.

The result is executive-level oversight of your AI operations. You set direction. Obey handles execution. Every action audited. Every boundary enforced.

Your agents. Your rules. Your runtime.

Every AI coding tool today operates in isolation. One agent, one terminal, one person watching. That doesn’t scale.

Running 10 agents across 5 projects requires 10 terminals, constant context switching, and no unified view of what’s happening. There’s no metering, no security boundaries, no audit trail.

Obey solves this by providing the runtime layer: a daemon that manages agent sessions, enforces campaign-scoped boundaries, meters token usage, and streams activity to wherever you need it.

The model is smart enough. The infrastructure to use it at scale is what’s missing.

Obey is that infrastructure.

The distinction matters. Planning and execution are fundamentally different concerns.

Festival answers: What work needs to happen? In what order? With what success criteria? It’s a workspace and methodology — campaigns, festivals, phases, sequences, tasks.

Obey answers: How do agents execute that work? With what providers? Under what constraints? With what proof?

Obey watches Festival’s filesystem for state changes. When a task is ready, Obey can spin up an agent session to execute it. When the agent completes, Obey records the result and Festival advances to the next task.

They’re designed to work together, but they’re independent systems. You can use Festival without Obey (manual execution). You can use Obey without Festival (ad-hoc agent sessions). Together, they’re a complete AI development stack.

Two layers. One stack. Complete control.

Obey’s session management is built on a pluggable adapter system. Each provider implements the same interface: start, send message, stream activity, stop.

This means switching providers is a configuration change, not a rewrite. Running multiple providers simultaneously is native — Claude Code on one project, Codex on another, both managed by the same daemon.

Sessions support grouping (coordinate multiple agents) and chaining (sequential execution pipelines). Parent-child spawning enables hierarchical agent orchestration.

All sessions are persisted, so daemon restarts don’t lose state. Activity streams can be consumed by any client — CLI, TUI, web dashboard, or mobile app.

One daemon. Many agents. Any provider. Full lifecycle control.

Security isn’t optional when agents have filesystem access. Obey enforces it at the runtime level.

Sandbox boundaries: Every agent session operates within a campaign-scoped boundary. Symlink-aware path validation prevents escape. File deny lists protect sensitive paths.

Allowlisted execution: Only approved commands (fest, camp, just, git) can be run through the execution sandbox. Subcommand manifests from CLI tools provide fine-grained restrictions.

Audit chain: An immutable, cryptographically chained log records every security-relevant event — command executions, denied operations, boundary violations. The chain can be verified for tampering.

Metering: Per-campaign quotas for token usage, execution time, and concurrent sessions prevent runaway costs and resource exhaustion.

Trust your agents to work. Verify everything they do.

Obey runs as a background daemon on your development machine. Clients connect over a local gRPC socket or remotely via the obey.app hub.

This means you can start an agent session from your laptop, walk away, and check on it from your phone. Activity streams in real-time. Session controls work from any client.

The hub synchronization layer maintains a WebSocket connection to obey.app, projecting your campaign state, festival progress, and agent activity to the cloud dashboard. Auto-reconnect with configurable backoff ensures reliability.

TUI for power users. Web for visibility. Mobile for on-the-go monitoring. Same daemon. Same state. Any surface.

Your runtime, accessible from everywhere.
